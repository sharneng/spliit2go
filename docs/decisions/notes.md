# Notes: links and markdown

Written 2026-10-13 ([#311](https://github.com/sharneng/spliit2go/issues/311)), with Kenneth.

## The problem

Notes were plain, selectable text. A pasted booking or receipt link couldn't be tapped, and someone who writes markdown saw its symbols instead of the formatting.

## Decisions

1. **Links in every note are tappable** in the expense details sheet, and open in the browser. An address runs from `http://` or `https://` to the next space; punctuation that ends a sentence after it isn't part of it, except a closing parenthesis the address opened, as in `https://en.wikipedia.org/wiki/Paris_(mythology)` (PR #312 review). A link that can't be opened says so in a snack bar.
2. **Markdown only when the note opts in.** Guessing whether a note is markdown is unreliable: a line starting with `-` or `1.` may or may not be a list. Most people don't write markdown, and their notes must look exactly as typed, so plain notes are never rendered.
3. **The choice lives in the note:** its first line is `<!-- markdown -->`. Spliit has no field for it, so this is the only way it travels with the expense to other devices. It's an HTML comment, which markdown renderers hide, so if the Spliit website or another app ever renders notes, the marker disappears there too. In plain-text views (spliit.app and spliit-ios today) it shows as a line of text.
4. **Nobody types the marker.** The form's Notes card has a **Markdown** switch that adds or removes it; the field never shows it. The switch shares a slim line under the field with the character count, both in the secondary color at the rows' size. **Preview**, a link on the Notes caption's line like Select all/none, shows the note as it will look, for every note, not only markdown: its links show, and a long note reads better. **Edit** puts the cursor back in the field (Kenneth on devices). An empty note is saved empty, without the marker. The marker counts toward Spliit's 5,000-character limit. Typing stops there, but turning the switch on for a note already near it can pass it: saving is then refused with how many characters too many, in Edit even from Preview, and nothing is cut (PR #312 review).
5. **Line breaks are kept as written**, as in a plain note (`softLineBreak`), and so are a markdown note's leading spaces: four make a code block (PR #312 review). Plain notes are still trimmed. Other rules are standard markdown, so a line right after a list item continues that item.
6. **Rendering:** `flutter_markdown_plus`, the maintained continuation of Flutter's discontinued `flutter_markdown`, styled from the theme, selectable as plain notes are.
7. **Images aren't downloaded** ([#325](https://github.com/sharneng/spliit2go/issues/325), from the [2026-10-14 architecture review](../reviews/2026-10-14-architecture-review.md) A6). A note's author chooses the image's address, and showing it would contact that host whenever someone opens the expense, a request the privacy policy doesn't cover. In the details sheet and Preview an image shows as its alt text (or "Image") with an open button that takes a web image to the browser; inside a link, a tap on the text opens the link, and the text is underlined in the link color so it looks like one ([#330](https://github.com/sharneng/spliit2go/issues/330)). The image builder isn't told which images are in a link, so the note is parsed again with the same markdown parser and settings, and each image is matched by its place in the note, not its address and alt text: the same image can appear both in and out of a link (PR #332 review). Showing images would need its own network, cache and privacy policy first.
8. **Only web links open:** `http` and `https`, as in a plain note. A markdown link to `tel:`, `file:` or an app's scheme says it can't be opened (#325).
